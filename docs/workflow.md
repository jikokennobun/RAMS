# 研究実行手順

1. `data/tasks.json` で `ready` かつ依存課題がすべて `done` の課題を選ぶ。
2. `npm run plan -- RAMS-Q001` で出典・関連主張を埋め込んだプロンプトを生成する。
3. `scripts/run-research.ps1 -TaskId RAMS-Q001` または対話中のCodexで研究する。
4. 発見結果を `research/reports/<task-id>-discovery.md` に保存する。定義・仮定・証明・証人・未解決箇所を残す。実行を完了したことと、課題を解決したことを区別する。
5. 別のレビューセッションで同じ定義・証拠を監査し、`<task-id>-audit.md` を作る。主張と監査を同じ文章で兼ねない。
6. 検証可能な証拠を台帳に登録して `npm run verify` を実行する。`proved` にはローカルの証明ファイルと監査ファイルが必要。
7. 根拠と限界を確認して小さくcommitする。次の課題を具体化する。

## 状態

| 状態 | 意味 |
| --- | --- |
| pending | 未監査・未証明 |
| proved | 完全な明示的証明と別の監査レポートがある |
| finite_checked | 明示された有限構造・範囲で全数検査済み |
| sampled | 有限サンプルだけを検査 |
| refuted | 前提を満たす証人と失敗する結論を確認済み |

ファイルの存在やCI成功は証明の正しさを保証しません。数学的レビューが必要です。文献上の新規性は別の状態として記録します。

## 計算と停止条件

有限検証器は各モデルでN/K/4を含む全公理を確認した後、ガード状態付きの項関数を飽和させます。各パラメータはその代数の全元を走ります。既定の関数数上限は10,000です。上限到達はエラーで終了し、完全判定として扱いません。大きな代数では状態空間が急増します。

実行ログ・日時付き最終応答はgit管理外の `research/runs/` に置き、採用する成果だけ `research/reports/` に整理します。

## 実行環境

研究用CLIは既存のCodexログインを使用します。APIキーやトークンはリポジトリに保存しません。GitHub ActionsはNodeの決定的検査だけを実行します。LLM研究の定期実行は、利用枠・頻度・課題を決めてから別途設定できます。
