共有チャットS001〜S003の既存本文取得記録、作業用定義、既存のpending主張を使用しました。添付原稿・ZIP・CSVは未取得のままです。8課題を登録し、原本に依存するgTFPP⇒gU・Mix崩壊は自動実行から除外しました。

## 実装と検証

`npm run verify` により28テストと既存3モデルの検査が通過しました。複数前提・追加仮定の保持、未監査規則の除外、不正な証明書・改ざんされたキャッシュの拒否、反例と受理済み規則の衝突を確認しました。

ランナーの3段階接続、blockedでの停止、失敗後の再開、文脈ハッシュ不一致時の拒否、排他lock、時間上限・ログ上限・UTF-8出力はテスト用の応答または短いNode子プロセスで検証しました。実際のCodexモデルを呼ぶ研究実行はまだ行っていません。したがってLLMが数学的課題を解いた、またはCLIと外部モデルの接続が実地検証済みとは主張しません。

Windowsの終了処理テストではtaskkillが制限下で失敗する場合があり、直接の子プロセス停止を必ず試みるよう修正して再検証しました。課題指定はWindowsのnpmの引数処理を避け、位置引数または `node scripts/research-system.mjs ...` を使います。

`npm run research:cycle` は62様相表を列挙し、NK4を満たす14モデルの閉包証明書を別評価器で再検査しました。実行範囲では打ち切りなし、受理済み規則との矛盾なし。出力のスナップショットを `research/examples/` に保存しています。

`npm run research:plan AUTO-001` により3役割のプロンプトを生成できました。`node scripts/hierarchy.mjs --seed=gFPP,gU --assume=N,K,4` の閉包と、証明書の単独再検査も実行済みです。
